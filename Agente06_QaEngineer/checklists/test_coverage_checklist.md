# Test Coverage Checklist

> Use when verifying coverage thresholds as part of Gate 4 evaluation.

---

## Pre-Check

- [ ] Coverage report is available (`coverage/index.html` or `coverage/lcov.info` or text summary)
- [ ] Report was generated by running `npx vitest run --coverage` (or equivalent)
- [ ] Report covers only the NEW/MODIFIED files in this PR (not the entire historical codebase)
- [ ] Coverage tool is Vitest built-in coverage — not Istanbul config on another framework

---

## New Business Logic Files

For each NEW file introduced in `features/[domain]/actions/`, `features/[domain]/[domain].service.ts`:

| File | % Lines | % Branches | Meets 80% | Meets 100% (if auth/critical) | Status |
|------|---------|-----------|-----------|------------------------------|--------|
| `features/[domain]/actions/[name].ts` | [X]% | [X]% | [YES/NO] | [YES/NO/N/A] | [PASS/FAIL] |

- [ ] Every new business logic file meets the 80% line coverage threshold
- [ ] `catch` blocks in Server Actions are exercised by the error path test
- [ ] The coverage report shows the error path was actually executed (not just the happy path)

---

## Auth Paths — 100% Required

Auth paths require 100% line coverage. No exceptions.

- [ ] `lib/auth.ts` or equivalent auth helpers: 100% coverage
- [ ] `const session = await auth()` check path: covered (both null and valid session cases tested)
- [ ] `if (!session?.user?.id)` branch: covered (the test case for unauthenticated user exercises this)
- [ ] IDOR ownership check: covered if applicable (`resource.userId !== session.user.id`)

---

## Critical Mutation Paths — 100% Required

Critical mutations (create/update/delete data) require 100% line coverage.

- [ ] Every `create` operation: success path AND error path covered
- [ ] Every `update` operation: success path AND error path covered
- [ ] Every `delete` operation: success path AND error path covered
- [ ] `auditLog()` call is exercised in the success path test
- [ ] `syncLog()` call is exercised in both success and finally paths (for cron jobs)

---

## Uncovered Lines Analysis

If any file is below threshold:

1. Identify the specific uncovered lines from the coverage report
2. Classify each uncovered block:
   - Auth guard: 100% required → `BLOCKED_QA_FAILURE`
   - Error handler / `catch` block: HIGH priority → `BLOCKED_QA_FAILURE` if business logic
   - Edge case / boundary: MEDIUM → `BLOCKED_QA_FAILURE` if 80% threshold violated
   - Dead code / unreachable: flag for removal, not a coverage failure
