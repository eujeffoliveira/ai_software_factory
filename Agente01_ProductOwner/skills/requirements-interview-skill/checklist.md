# Requirements Interview Skill — Checklist

## Before Execution
- [ ] Briefing has been read in full before generating questions
- [ ] Questions already answered in the briefing have been identified and removed from the question list
- [ ] Technology questions have been removed (database, framework, API design choices are not for this phase)
- [ ] Questions are categorized into the 6 elicitation areas

## During Execution
- [ ] Each question has a specific, answerable form (yes/no, or a concrete value/list)
- [ ] Questions are numbered and categorized
- [ ] BLOCKING questions are prioritized and clearly marked
- [ ] Answers received are recorded accurately (verbatim or summarized — not paraphrased to a different meaning)
- [ ] For each answer: action item is identified (BR-NNN, OQ-NNN, assumption, or no action)
- [ ] Follow-up questions generated by unexpected answers are recorded as additional questions

## Output Validation
- [ ] `Requirements_Interview_Log.md` follows the template structure from `templates/Requirements_Interview_Log.md`
- [ ] All 6 question categories are present in the log (even if empty with a note)
- [ ] Every unanswered question has a corresponding OQ-NNN entry in `Open_Questions.md`
- [ ] Every OQ-NNN has: question text, impact, criticality, and owner
- [ ] BLOCKING questions have explicit deadlines
- [ ] Session summary accurately reflects what remains unclear
- [ ] No open questions are listed without a criticality level

## Runtime Knowledge Policy
- [ ] Skill reads only from `Agente01_ProductOwner/` and project inputs — never from `context/`, `lib/`, or raw books
- [ ] Elicitation question patterns come from `knowledge/heuristics.md` and `knowledge/principles.md`
- [ ] No PDFs or external bibliography sources are accessed at runtime
